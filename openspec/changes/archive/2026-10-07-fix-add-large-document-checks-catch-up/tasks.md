## 2. Front matter inside the Markdown parser

This section replaces section 1's `yamlFrontmatter` wrapper (1.1) and its timed test (1.3), as `design.md` decides.

- [x] 2.1 A new file, `src/editor/front-matter.ts`, exports a `MarkdownConfig`, `frontMatter`. It defines a block node `Frontmatter` and the nodes `DashLine` and `FrontmatterContent`, and has one block parser, named `Frontmatter`, with `before: "LinkReference"`. The parser matches only a line that starts at document position 0 and whose text is exactly `---`. It consumes lines up to and including the next line whose text is exactly `---`, or to the end of the document if there's none. `Frontmatter` spans from 0 to the end of its last line, without that line's break. Each `---` line is a 3-character `DashLine`, and the text between them, if any, is one `FrontmatterContent`.
- [x] 2.2 `markdownMode()` in `src/editor/language.ts` returns `new LanguageSupport(new Language(commonmarkLanguage.data, (commonmarkLanguage.parser as MarkdownParser).configure([GFM, quiroMarkdownTags, frontMatter]), [], "markdown"))`. Its signature is unchanged. No file under `src/` imports `@codemirror/lang-yaml` or `parseMixed`. The comment in `language.ts` says the whole document is one Markdown parse with no nested parse, because a nested parse reports position 0 and makes typing discard background parsing progress.
- [x] 2.3 The comment in `src/editor/blocks.ts` that says front matter ends after its closing line break is reworded to match the new ranges. The file's code is unchanged.
- [x] 2.4 A new jsdom test file in `src/editor/` parses each input in `design.md`'s front-matter table with `markdownMode().language.parser`. It checks that the first child of the top `Document` is a `Frontmatter` node exactly where the table says front matter, and that it ends at the end of the document in the `...` and unterminated cases.
- [x] 2.5 `src/editor/parse-progress.test.ts` is rewritten as `design.md` describes, and no longer reads any clock. It starts a parse of `generateLargeDocument(DEFAULT_LARGE_DOCUMENT_SEED)` with `markdownMode().language.parser.startParse`, calls `advance()` 1,000 times and expects `parsedPos` above 0, then 1,000 more times and expects `parsedPos` to be higher.
- [x] 2.6 `src/editor/fixtures/dialect.tree.txt` differs from its previous version only in that lines 2 to 13 are replaced by `Frontmatter 0-30`, `DashLine 0-3`, `FrontmatterContent 4-26` and `DashLine 27-30`.
- [x] 2.7 Besides 2.4's new file and 2.5's rewrite, no test file is modified. `package.json` and `package-lock.json` are unchanged. `npm run lint`, `npm test` and `npm run build` pass in the gate.
