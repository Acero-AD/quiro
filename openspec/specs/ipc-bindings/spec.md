## Requirements
### Requirement: Frontend calls Rust only through generated bindings
All frontend calls to Rust commands SHALL go through `src/bindings.ts`, which SHALL be generated by tauri-specta and checked in. No frontend file other than `src/bindings.ts` SHALL import `@tauri-apps/api/core`.

#### Scenario: Calling a command
- **WHEN** frontend code calls the `ping` command
- **THEN** it calls `commands.ping` imported from the generated bindings, not `invoke` with a command-name string

### Requirement: Stale bindings fail the gate
`cargo test` SHALL fail when `src/bindings.ts` differs from what the Rust commands and types generate. The failure message SHALL contain the complete freshly generated file between a `----- BEGIN src/bindings.ts -----` line and a `----- END src/bindings.ts -----` line. `npm run build` SHALL fail when frontend code doesn't match the bindings' types.

#### Scenario: Renaming a Rust field without regenerating
- **WHEN** a field of `PingReply` is renamed in Rust and `src/bindings.ts` isn't updated
- **THEN** `cargo test` fails, and its output contains the full expected `src/bindings.ts` between the marker lines

#### Scenario: Frontend misuses a binding
- **WHEN** frontend code reads a field that doesn't exist on the generated `PingReply` type
- **THEN** `npm run build` fails with a type error

### Requirement: Bindings are regenerated only on request
The bindings SHALL be rewritten only when `cargo test` runs with `UPDATE_BINDINGS=1`. The app SHALL NOT export bindings when it starts, and a plain `cargo test` SHALL NOT modify `src/bindings.ts`.

#### Scenario: Explicit regeneration
- **WHEN** `cd src-tauri && UPDATE_BINDINGS=1 cargo test` runs after a change to an IPC type
- **THEN** `src/bindings.ts` is rewritten and the drift test passes

#### Scenario: Ordinary test run
- **WHEN** `cargo test` runs without `UPDATE_BINDINGS`
- **THEN** `src/bindings.ts` is left unchanged whether or not the test passes

### Requirement: Data-carrying IPC enums use adjacent tagging
Every enum that carries data across IPC SHALL be serialised with adjacent tagging (`#[serde(tag = ..., content = ...)]`).

#### Scenario: Ping error shape
- **WHEN** `ping` fails because the message is too long
- **THEN** the error crosses IPC as `{"kind":"tooLong","data":{"max":256}}`

### Requirement: Ping reference command
Quiro SHALL provide a `ping` command that takes a request with a `message` and replies with the message echoed and the app version. It SHALL return a typed error for an empty message, and for a message longer than 256 characters. The starter `greet` command SHALL NOT exist.

#### Scenario: Successful ping
- **WHEN** the frontend pings with the message "hello"
- **THEN** the reply is `{"echo":"hello","version":"<crate version>"}`

#### Scenario: Empty ping
- **WHEN** the frontend pings with an empty message
- **THEN** the result is the error `{"kind":"empty"}`

#### Scenario: Oversized ping
- **WHEN** the frontend pings with a 257-character message
- **THEN** the result is the error `{"kind":"tooLong","data":{"max":256}}`
